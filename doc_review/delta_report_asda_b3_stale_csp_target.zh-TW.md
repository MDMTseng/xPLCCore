# ASDA-B3-E 在 CSP 模式下週期性取用錯誤週期的目標位置

**收件：** 台達電子 技術支援（伺服 / EtherCAT）
**驅動器：** ASDA-B3-E（三台，EtherCAT），ASDA-Soft 顯示韌體版本
`B3-E-Ver22106-Sub 212, 96, L=120`
**測試日期：** 2026-09-30 至 2026-10-01

## 摘要

在 CSP 模式、DC SYNC0 同步下，驅動器會週期性地取用錯誤 EtherCAT 週期的
目標位置（0x607A）。每隔 2.4–3.6 秒出現一次突波，持續數 ms 到數十 ms。
突波期間：
- 驅動器內插後的命令位置斜率會跳成正常值的 2 倍或 3 倍；
- 命令位置會在 1/8 ms 內跳動最多約 200 PUU。

在 delta 機械手臂上，這會造成輕微的撞擊感和振動。

完全不經過運動函式庫時問題依然存在。我們的 PLC 程式直接把 controlword
和一條完全等速的斜坡（每 1 ms 週期精確 +145 PUU）寫進 RxPDO，驅動器仍然
出現突波。

主站端是乾淨的：
- 每個週期送出的目標都很平順，已在 PLC 內部及匯流排上（同一個 frame 中的
  獨立 DC 從站）驗證；
- 沒有遺失 frame；
- 驅動器本身的同步計數器一直為 0（0x1C32:0B、:0C、:20）。

突波的特性：
- 與速度無關；
- 三台驅動器的發生率相近；
- 每次 EtherCAT 啟動的發生率不同。

## 最小測試案例：不使用運動函式庫

- 運動函式庫不控制這台驅動器，由 PLC 應用程式直接寫 controlword（0x6040）
  和目標位置（0x607A）。
- 動作順序：
  1. CiA402 啟用：0x06、0x07、0x0F。
  2. 之後每個 1 ms 週期精確 **+145 PUU**（約 0.1°/s），走 3° 再走回來。
- 每個週期把驅動器的位置命令值 **0x6062**（放在 TxPDO 中）和我們送出的
  目標比對。

正常情況下，0x6062 等於 **3 個週期前**送出的目標。結果：

| 測試 | 週期數 | 0x6062 = 4 個週期前的目標 | = 2 個週期前的目標 |
|---|---|---|---|
| 1.5°，每週期 +145 | 29,892 | 1,563（5.2 %） | 24 |
| 1.5°，每週期 +145 | 29,892 | 1,719（5.8 %） | 21 |
| 3°，每週期 +145 | 59,782 | 1,997（3.3 %） | 27 |
| 3°，**每週期 +72（半速）** | 120,394 | 4,366（3.6 %） | 73 |

發生率與速度無關：速度減半、時間加倍，次數也跟著加倍。

突波期間每週期的增量（PUU）：

```
送出  (607A):  145 145 145 145 145 145 145 145 145 145 145  145 145
驅動器(6062):  145 145 145   0 145 145 145 290 290 -145 145 145 145
```

這次突波中，驅動器的延遲從 3 → 4 → 3 → 2 → 3 個週期變化，表示它有時取到
比平常舊的目標，有時取到比平常新的目標。

### 週期性

120 秒內共 44 次突波，間隔 2.37–3.57 秒（平均 2.8 秒）。間隔大致以
**2.37 → 2.58 → 3.5 秒**重複，一輪約 8.5 秒。最大的幾次突波約每
8.3–8.5 秒出現一次。

突波起始時間（ms）：374, 2962, 5346, 8896, 11492, 13858, 17327, 19994,
22389, 25588, 28539, 30912, 33898, 37043, 39437, 42217, 45574, 47941,
50527, 54102, 56471, 59052, 62524, 64997, 67579, 70399, 73519, 76095,
78545, 82040, 84600, 86993, 90548, 93131, 95501, 99065, 101666, 104040,
107400, 110186, 112561, 115712, 118684。

這種規律顯示：驅動器內部取用新目標的時間點相對 SYNC0 在漂移，並週期性地
掃過新 PDO 資料生效的那個時刻。可能是驅動器控制時脈與 SYNC0 之間的拍頻，
或是驅動器同步迴路的週期性修正。

## 已排除的因素

| 懷疑對象 | 檢查方式 | 結果 |
|---|---|---|
| 運動函式庫 / 路徑規劃 | 完全繞過：PLC 程式直接寫 0x6040 和 0x607A，每週期固定 +145 / +72 PUU | 仍有 3.3–5.8 % 的週期出錯，且為週期性突波 |
| 主站軌跡 | 每週期計算命令位置的二階差分（浮點及整數） | 平順；超過 1,000,000 個週期無異常 |
| 寫入 frame 的資料 | 每週期以唯讀方式讀取 0x607A 的 process image | 每個週期都等於預期值 |
| 遺失 frame / 匯流排錯誤 | 主站統計 | 0 遺失，0 TX / RX 錯誤 |
| 線路末端 frame 相對 SYNC0 的時序 | ESP32 + LAN9252 從站（線路最末端，DC SYNC0）在每個 SYNC0 讀取週期計數器和驅動器目標的副本，並量測 frame 到達時間 | 0 次過期，0 次跳格。frame 在 SYNC0 後 660–825 µs 到達，距下一個 SYNC0 至少 175 µs |
| 速度 | 每週期 +145 及 +72 PUU | 發生率相同 |
| 命令餵送方式 | 每批 8 段運動並停頓 vs 連續運動 | 發生率相同 |
| 週期時間 | 2 ms 取代 1 ms | 出錯區段比例相同 |
| P3.009.Z（讀取延遲） | 一台由 0 改為 3 | 無變化 |
| ASDA-Soft USB 監控（AL304 提示） | 拔除 USB | 仍有 3–4 % |
| 驅動器自身同步診斷 | 事件發生時讀取 0x1C32:0B、:0C、:20 | 一直為 0 |

## 不同啟動之間的差異

單軸，SyncOffset 50 %。發生率為運動中 0x6062 晚一個週期的比例。

| 條件 | 發生率 |
|---|---|
| 三次 EtherCAT 啟動，設定完全相同 | 0.04 %、3.13 %、4.46 % |
| 同一次啟動，約 5 分鐘內伺服 off/on 四次 | 3.05 %、3.43 %、3.87 %、4.16 % |
| 主站 SyncOffset 30 / 40 / 50 %（各一次啟動） | 5.62 % / 3.42 % / 0 %（50 % 在另一次啟動為 4.3 %） |

三台驅動器的發生率相近。
